# Implementation and acceptance plan

Scope: extend the verified native-file hygiene boundary with a once-per-project user-consent onboarding flow; publish this hygiene-only component separately. The current request authorizes implementation/public sharing; no personal/business data or raw native traces enter the repository.

1. Consent state machine: worker gpt-6-sol medium; selected lead verifies hostile and normal local event tests. No model/network/transcript access from runtime. Actual native user decisions, not model-authored tool sentinels, authorize organizing or skipping.
2. Standalone installer plus existing-kit integration: selected lead implements; independent strongest available review. Keep unrelated hooks, avoid duplicated guards, preserve recoverable sources/state and native trust gates.
3. Native lifecycle and publication: reuse bounded subscription transports; explicit tests prepared before inference; at most three meaningful trials per host, no API-key fallback. Compare same process before activation and next prompt after activation; actual prompt question, premature Write denial, approval/review/Old/Assets/complete/resume, plus skip and fresh install replay.

Known boundaries remain: native callbacks must be registered; arbitrary shell/MCP writes, every semantic dependency, arbitrary old-process definition reload, hidden/compacted chat history and automatic general source-file archival are not universally proven. No historic transcript scraping. Available conversation history informs model decisions; checked filesystem evidence constrains actual moves.

## Current measured local acceptance

The selected lead independently ran 84 package tests and all 247 legacy tests against an integrated disposable public-core copy. Only an invalid PNG fixture header was normalized in the disposable legacy copy; no assertion was relaxed. Independent gpt-6-astra/high review reproduced capacity-before-move, dynamic SVG, native envelope, concurrent update and policy rollback failures through three review passes. All agreed replays passed. The lead separately tested the subsequently identified staged-enable post-commit branch.

Builders used bounded gpt-6-sol/medium assignments; native-controller preparation uses gpt-6.1-sol/high. The lead owns final QA. Runtime scripts contain no model/network client. Native subscription execution was bounded by frozen source hashes, request/turn caps and a restoration watchdog.

The first real trial per host failed at consent flow: the integrated operator core already contained an advisory-only transformation. Claude Code used claude-haiku-5-5 and forwarded six subscription requests; Codex used gpt-6-luna and started three native turns, with no measurable provider request counter. No API-key fallback was used. Preparation incorrectly accepted warning text as denial evidence. Future negative checks must require the native decision shape, actual file-tool identity, unchanged project bytes and source/session-bound receipts. Repeating the same model test without correcting that preparation would waste quota.

Both watchdogs exited successfully; all frozen operator source hashes and settings were restored. Persistent activation remains withheld. The operator's advisory policy must be reconciled explicitly before any attempt to replace it. Four anonymous public-clone old/new installed-command scenarios passed without model requests; they are not native host evidence.
