# Context-aware file organization

This classification was checked against four real multi-output project trees using metadata only. The largest contained 1,772 files. Private project names, filenames and business content are not distributed.

| Role | Typical types | Placement and checks |
| --- | --- | --- |
| Application/source | HTML, CSS, JS, Python | Preserve required entrypoints and relative paths. HTML may instead be a presentation deliverable. |
| Editable masters | SVG, PPTX, DOCX, design sources | Keep the current editable source. Exported PDF/PNG is not automatically its replacement. |
| Final deliverables | PDF, presentation HTML, upload images, ZIP packages | Group by actual product or audience when appropriate; keep independent formats that still serve a purpose. |
| Supporting assets | Images, fonts, icons, references | Prefer Assets subfolders only after checking incoming and outgoing references. |
| Working data | CSV, XLSX, JSON, SQLite | Keep source data, analysis outputs and application databases distinct. Configuration JSON stays where required. |
| Documentation and verification | Markdown, scripts, tests, evidence | Keep maintained project instructions and required checks. Do not archive an entire QA directory by name. |
| Older versions | Any supported reviewed type | Old/YYYY-MM with original relative path, name, timestamp, bytes and recovery manifest. |

Extensions alone never establish role, replacement or disuse. Current source and final exports may both be required. Archives may be the intended installable product. Lock files, credentials, required configuration and protected entrypoints do not move.

## Existing folders

The first delivered native user prompt after activation asks once for organization consent. No retroactive bulk cleanup runs at installation. Approval authorizes reviewed organization, including a differing prior version when available conversation history clearly identifies its retained replacement. The review records that evidence and verifies both hashes; code cannot authenticate the semantic truth of history.

Uncertain files stay in place. Missing or compacted chat history is not reconstructed by scraping transcripts. Unsupported dependencies or bounds cause refusal, not a guessed move.

## Maintained navigation

FOLDER-GUIDE.md records the actual project purpose, entrypoints, observed type locations, retained required structure, Assets/Old rules and maintenance notes. The model supplies contextual roles from available conversation; code checks real paths and renders the managed structure. Structural changes refresh it; identical structure does not rewrite it on every prompt.

A new empty folder receives its guide without legacy cleanup. Existing folders receive a contextual guide only through the organization/material-work flow. Foreign or tampered guides are not overwritten.

## Explicit boundaries

Known native file events are guarded. Shell, connectors, background processes and missing host callbacks remain uncovered. Local literal/stem/reference checks are conservative, not universal dependency analysis. No source can guarantee 100% correctness across arbitrary projects.
